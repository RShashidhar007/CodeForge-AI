## Type definitions and service layer

All GitHub integration types (GithubOAuthUrlResponse, GithubRepository, ImportRepositoryRequest, ImportStatusResponse) and code search types (SemanticSearchRequest, SearchResult, SemanticSearchResponse) use camelCase field names. The apiClient automatically transforms backend snake_case responses via a response interceptor, so the type definitions match the transformed shape.

Services follow the established pattern: export an object with methods that return `apiClient.{method}(url, data).then(r => r.data)`. The githubService includes six endpoints (OAuth URL, callback handler, list repositories, import repository with 202 Accepted response, get import status, unlink tokens). The codeSearchService has a single semanticSearch method posting to `/code/search`. Both use explicit TypeScript return types for all methods.

Error handling separates GitHub-specific errors (parseGithubError) from general API errors (extractErrorMessage from apiClient). The GitHub handler maps 401 to auth failed, 403 with rate limit message to rate limit exceeded, 404 to not found, 429 to too many requests, and 502 to GitHub API unavailable. All errors surface via toast notifications positioned top-right with 4-second auto-close.

## GitHub OAuth and popup communication

The OAuth flow calls getOAuthUrl, opens `window.open(authorizationUrl, 'GitHub OAuth', 'width=600,height=700')`, and listens for postMessage events from the callback page. Iteration 2 added popup blocker detection: if window.open returns null, a toast error informs the user to allow popups. The parent window uses addEventListener with cleanup when the popup closes or a message arrives.

The callback page reads code and state from query params, calls handleOAuthCallback, and posts `{type: 'github-oauth-success'}` or `{type: 'github-oauth-error', error: message}` to window.opener using postMessage with origin '*'. Iteration 2 added a mounted flag guarding all setState calls to prevent updates after component unmounts. On success, the page shows a green checkmark and auto-closes after 1 second. On error, it shows a red X with the error message and a manual close button.

## Repository import with progress polling

The import modal fetches projects on mount using projectService.listProjects, selects the first project by default, and shows a dropdown for project selection. Clicking Import extracts owner and repo from the repository's fullName (e.g., "owner/repo"), calls githubService.importRepository with the selected projectId, and immediately starts polling getImportStatus every 2 seconds.

The polling useEffect depends on importing and selectedProjectId. It declares `let mounted = true` at the top, checks `if (!mounted) return` before every setState, and returns cleanup setting `mounted = false` and clearing the interval. This prevents setState calls after unmount, addressing the iteration 1 finding. The modal tracks status states (PENDING, CLONING, INDEXING, COMPLETED, FAILED) and disables the close button while in progress to prevent accidental dismissal.

Progress display uses the ProgressBar component showing progressPercentage from the backend response, with a label indicating processed files and embedded chunks. Success shows a green alert with CheckCircle icon. Failure shows a red alert with the error message.

## Semantic search with debouncing

The search panel accepts projects array, selectedProjectId, and onProjectChange callback as props. It maintains local state for query, debouncedQuery, results, loading, and expandedResults (a Set of result keys for expand/collapse tracking).

Debouncing uses two useEffects: the first sets a 300ms timeout updating debouncedQuery when query changes, returning cleanup that clears the timeout. The second watches debouncedQuery and selectedProjectId, calling performSearch when both are non-empty. The iteration 1 review noted missing mounted guard in performSearch; iteration 2 added `let mounted = true` at the top of the search effect, checks before setResults and setLoading, and returns cleanup with `mounted = false`.

Results render as clickable cards showing FileCode icon, file path in monospace font, line numbers (startLine-endLine), optional language, and a score badge (percentage with green background if >70%). Clicking toggles the result key in expandedResults Set. Expanded state shows code content in a pre/code block with max-height 300px, overflow auto, monospace font, #f5f5f5 background, and word-wrap for long lines.

Empty states: "No results found" when debouncedQuery is set but results are empty, "Enter a search query to find relevant code" when no query exists. Both show a large FileCode icon with muted color.

## AI page tabbed interface

The page adds activeTab state ('chat' | 'search') and renders tab buttons before the main content area. MessageSquare icon for Chat, Search icon for Code Search. Active tab gets .active class with blue background and text. All existing chat state (messages, input, loading, conversationId, conversations) is declared at the component level outside the conditional rendering, so switching tabs preserves chat history.

The chat tab wraps the existing messages container, input form, sidebar with conversation list, and sources display. The search tab renders SemanticSearchPanel with projects, selectedProjectId, and onProjectChange props. Projects load on mount via projectService.listProjects. If projectId exists in URL params, it initializes selectedProjectId; otherwise it selects the first project after loading.

Tab styles use flexbox with gap, hover states change background to light gray, and active state uses blue background with blue text. Responsive breakpoints: at 768px tabs reduce padding, at 480px tabs stack vertically.

## Code block rendering and clipboard

The renderMessageContent helper parses message content using regex `/```(\w+)?\n([\s\S]*?)```/g` to detect markdown code blocks. It splits content into text paragraphs (rendered as p tags with line breaks) and code blocks (rendered as CodeBlock components). A comment documents the limitation: this regex-based parser doesn't handle escaped backticks or nested code blocks, and recommends a dedicated parser library like react-markdown for complex cases. This is an acknowledged trade-off for simplicity.

The CodeBlock component maintains copied state (boolean), renders a dark header (#2d2d2d background) with language label (uppercase) and copy button. The copy button checks `if (!navigator.clipboard)` before attempting copy, showing a toast error if unavailable. Iteration 2 added this check plus a disabled state and tooltip when clipboard API is unavailable (non-HTTPS contexts except localhost). On successful copy, the button shows "Copied!" with Check icon for 2 seconds.

Code area renders as pre.code-block with #1e1e1e background, #d4d4d4 text color, Monaco/Menlo/Ubuntu Mono font stack, 0.85rem font size, and overflow-x auto for horizontal scroll on long lines.

Timestamps display below each message using `new Date(message.createdAt).toLocaleTimeString()`. User messages show timestamps with rgba(255,255,255,0.7) color, assistant messages use var(--color-muted).

## Routing and navigation

App.tsx adds three routes: `/github/callback` as a public route outside ProtectedRoute (no auth required, renders GithubCallbackPage directly), `/github` inside MainLayout protected by RoleRoute with allowedRoles CANDIDATE and RECRUITER (renders GithubIntegrationPage), and `/ai/:projectId?` also protected by the same RoleRoute (renders AIPage with optional projectId param).

Navbar adds GitHub links for CANDIDATE and RECRUITER roles using the Code icon from lucide-react (Github icon not available in lucide-react 1.48.0). The link renders icon and label, with an optional checkmark badge when user.githubConnected is true. The githubConnected field was added to the User interface in types/auth.ts as optional boolean.
